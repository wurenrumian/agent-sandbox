---
title: "08 何时不需要沙箱"
description: "避免过度设计的决策树与代价分析。"
---

不要为了「安全」给所有东西套沙箱，成本很高。

## 8.1 不需要的情况

- 只是结构化函数调用（查天气、查数据库）
- 只在自家可信环境跑固定流程
- 执行的是你自己写的、输入可控的代码

## 8.2 需要的情况

- 任意代码 / 任意 shell 执行
- 不可信输入（用户内容、外部网页、第三方文档）驱动执行
- 多租户、面向公众

> **判断口诀**：只要出现「任意代码 / 任意 shell / 不可信输入驱动执行」，就上沙箱。

## 8.3 决策树

```
需要执行代码吗？
├─ 否 → 普通 tool 调用即可，不需要沙箱
└─ 是
   ├─ 代码是「固定流程、你自己写的、输入可控」吗？
   │  ├─ 是 → 直接跑，加基本限额即可
   │  └─ 否
   │     ├─ 输入来自不可信来源吗？（用户 / 网页 / 文档）
   │     │  ├─ 否 → 视风险，可先用 Docker
   │     │  └─ 是 → 必须沙箱（默认断网 + microVM/gVisor）
   │     └─ 多租户 / 面向公众吗？
   │        └─ 是 → 强隔离 microVM + 每会话独立
```

## 8.4 过度设计的代价

| 代价 | 说明 |
|---|---|
| 延迟 | 每次执行多一次环境创建 / 网络往返 |
| 成本 | 环境常驻、资源浪费 |
| 复杂度 | 多一层编排、多一处故障点 |
| 体验 | 简单任务被拖慢 |

## 动手练习 8

回顾你系统里所有工具，标出哪些其实不需要沙箱（可以降级为普通 tool）。
