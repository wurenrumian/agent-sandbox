## 1.1 两种沙箱的对比

| | 传统安全沙箱 | Agent 沙箱 |
|---|---|---|
| 目的 | 防坏代码破坏系统 | 让 Agent 安全地做事 |
| 主视角 | 防御 | 赋能 |
| 生命周期 | 长期、固定 | 短、一次一换 |
| 接口 | 系统调用拦截 | API / SDK / MCP |
| 头号风险 | 沙箱逃逸 | 数据外泄 |

## 1.2 一句话定义

> Agent 沙箱 = 一个远程、可编程、一次性（或可持久）的计算环境，通过 API / MCP 暴露给 Agent 调用。

**拆开看关键词：**

- **远程**：通常在云端 / 独立主机，不和 Agent 主进程同命
- **可编程**：能被 API 创建、执行、销毁
- **一次性 / 可持久**：两种模式都要支持
- **API / MCP**：Agent 通过工具调用来使用它

## 1.3 它在 Agent 架构里的位置

```
┌─────────────┐     tool call      ┌──────────────┐
│  LLM / Agent │ ─────────────────► │   Sandbox    │
│   （大脑）    │ ◄───────────────── │  （手脚）     │
└─────────────┘   执行结果 / 文件    └──────────────┘
```

大脑负责思考，沙箱负责执行。二者解耦，才能各自独立扩展与替换。
