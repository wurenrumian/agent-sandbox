## 4.1 全景图

```
Agent Loop (LLM)
   │  tool call: run("python train.py")
   ▼
┌───────────────────────────────┐
│      Sandbox Control Plane     │   创建 / 路由 / 鉴权 / 配额 / 快照
└───────────────────────────────┘
   │
   ▼
┌───────────────────────────────┐
│   隔离后端 (Container /        │   真正执行
│   microVM / gVisor / WASM)     │
└───────────────────────────────┘
   │
   ▼
返回 stdout / stderr / exit code / 文件 diff → 回到 Agent
```

## 4.2 两个面的职责

| | 控制面 | 数据面 |
|---|---|---|
| 管什么 | 环境怎么来、活多久、能碰什么 | 真正跑代码 |
| 关键能力 | 调度、鉴权、配额、快照、路由 | 隔离、执行、IO |
| 常见实现 | 有状态服务 + 数据库 | microVM 池 / 容器池 |

**为什么分开？**
控制面要「秒级调度」，数据面要「强隔离」。分开后可以各自优化：数据面预热成**资源池**，控制面负责快速分配。

## 4.3 一次执行的完整时序

```
Agent          控制面            数据面
  │  create ────►│                 │
  │              │ 分配/预热 ─────►│
  │◄── sandbox_id┤                 │
  │  exec ──────►│                 │
  │              │ 转发命令 ──────►│  执行
  │              │◄── stdout ──────│
  │◄── result ───┤                 │
  │  destroy ───►│                 │
  │              │ 回收/销毁 ─────►│
```

## 4.4 关键设计点

| 设计点 | 说明 |
|---|---|
| **预热池（warm pool）** | 提前起好一批环境，规避冷启动 |
| **会话粘性** | 同一会话路由到同一环境，保证有状态 |
| **配额与鉴权** | 每个用户 / 会话独立限额 |
| **快照** | 支持暂停 / 恢复 / 分叉 |
| **可观测** | 命令、耗时、资源用量全量记录 |
