## 2.1 六个刚需

| 需求 | 具体表现 | 没有沙箱会怎样 |
|---|---|---|
| 执行不可信代码 | LLM 会幻觉、写错、被注入 | 直接污染宿主环境 |
| 有状态 | 改文件 → 再跑 → 看结果 | 每步都从零开始，做不了多步任务 |
| 可回滚 | 出错就丢弃重来 | 环境被搞脏，无法恢复 |
| 可并行 | 多个子任务同时跑 | 串行慢，且互相干扰 |
| 可观测 | 看 stdout / 文件变化 / 耗时 | 出问题无从排查 |
| 可回收 | 用完即销毁 | 资源泄漏、成本失控、残留风险 |

## 2.2 一个典型的多步任务

```
用户：帮我把 data.csv 清洗后算平均值，画个图

Agent:
  1) 沙箱内写 clean.py
  2) 运行 → 报错（缺 pandas）
  3) pip install pandas
  4) 重跑 → 成功，生成 result.csv
  5) 写 plot.py 画图 → 生成 chart.png
  6) 把 chart.png 传出来给用户
```

注意第 2–4 步：**有状态 + 可观测 + 可安装依赖**，这正是沙箱要提供的。

## 2.3 对比：没有沙箱时 Agent 的处境

| 场景 | 直接在本机跑 | 在沙箱里跑 |
|---|---|---|
| 代码删错文件 | 真删了 | 沙箱销毁，无事发生 |
| 装了个恶意包 | 宿主中招 | 隔离，销毁即清 |
| 死循环 / 占满内存 | 拖垮本机 | 触发限额，被 kill |
| 并发跑 10 个任务 | 互相干扰 | 每任务独立环境 |
