把这章当成**需求清单**，选型或自建时逐条打勾。

## 3.1 能力清单

- **文件系统**：读 / 写 / 上传 / 下载，支持挂载数据卷
- **Shell / PTY**：交互式终端（很多 Agent 依赖 bash）
- **多语言运行时**：Python、Node、Go……
- **包管理**：`pip install` / `npm i`（**同时是风险源**）
- **网络策略**：默认拒绝 or 白名单出网（**最关键的安全开关**）
- **快照 / 分叉**：保存状态、复制多份并行探索
- **生命周期管理**：超时、保活、暂停 / 恢复、持久卷
- **可观测 / 审计**：日志、命令记录、资源用量
- **接口层**：SDK / HTTP API / MCP server

## 3.2 优先级排序（务实版）

| 优先级 | 能力 | 理由 |
|---|---|---|
| P0 | 文件系统、Shell、网络策略、超时 | 没这些跑不起来 / 不安全 |
| P1 | 多语言、包管理、可观测 | 决定好不好用 |
| P2 | 快照 / 分叉、持久卷 | 决定能不能做高级场景 |

## 3.3 每一项的常见坑

| 能力 | 常见坑 |
|---|---|
| 文件系统 | 挂载了宿主敏感目录；没有配额导致塞满磁盘 |
| Shell / PTY | 命令没超时，一条 `sleep infinity` 卡死 |
| 包管理 | 默认从公网装包，引入供应链风险 |
| 网络 | 图省事给了 `bridge`，等于全开 |
| 快照 | 快照含敏感数据，恢复时越权访问 |
| 生命周期 | 忘了回收，僵尸环境堆积、账单暴涨 |
